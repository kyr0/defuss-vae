# vae.py CLI

The command-line interface behind the skills and hooks. Every command takes `--repo` (default `.`, resolved to the enclosing git root) and exits 0 when its claim holds and 2 when it does not (`swarm status`: 1 when an agent needs the orchestrator), so scripts and CI can branch on it.

```bash
python3 plugin/scripts/vae.py gate --repo .
```

| Command | What it does | Exit 0 when |
|---|---|---|
| `init` | Scaffolds what's missing: `.vae/`, `Makefile`, `.gitignore` lines, the managed `AGENTS.md` block and, on a GitHub remote, the CI workflow (unless `CONFIG["ci"]` is `False` or a workflow already runs the verification). Never overwrites. | always |
| `gate [--session ID]` | Runs verify, review and docs, in that order, for a session (default: the one whose state changed last) and prints what's missing. | `VERIFIED[gate]=true` |
| `verify [--json] [--changed PATH]...` | The verifier alone, on the current changes or the given paths. | every required check passes |
| `prose [--fix] [PAGE]...` | Static prose check of doc pages (default: every Markdown page, and the HTML pages `CONFIG["prose"]["html"]` names). `--fix` first applies the replacements that cannot change meaning; symbols standing in for words stay findings for a rewrite. | no findings |
| `edit start PAGE [--model ID] [--engine]` | Snapshots PAGE into `tmp/vae/edit/<page>-<stamp>-<hex>/` and prints the contract and part 1 for the agent's review; with `--engine` the configured model reviews every part (review, summary memory, audit) and the run finishes on its own. | the run started; `--engine`: `VERIFIED[edit.review]` |
| `edit submit --run RUN --part N --findings FILE --confidence high\|medium\|low [--decisions FILE]` | Checks the agent's findings for part N (strict JSON, pro-edit's schema, quotes in the part, no open replacement, protected terms, evidence read and, with a decision model, supporting its comment; after a rejection, no `hoch` issue that lost the evidence it cited). Below `high`, or with an issue at `sicherheit: mittel`, the engine reviews the part and the agent submits the consensus with `--decisions`. Prints the next part, or finishes the run with `final.json` and `review.html`. | the part is accepted |
| `edit apply --run RUN` | Writes every resolved replacement into the page in one write, refusing when the page changed after the snapshot; with typed decisions configured, holds back a replacement judged a meaning change. Records `applied.json`, lists the open findings. | applied |
| `edit show --run RUN [--part N]` / `edit resume --run RUN` | Lists the findings with page lines / continues a failed engine run from its last step. | always / `VERIFIED[edit.review]` |
| `edit serve [--stop]` | Starts the repository's review server (127.0.0.1, rooted at `.vae/doc-reviews/`) when none answers and prints its address; `--stop` stops it. A finished review starts it on its own. | always |
| `comments FOLDER\|FILE` | Reads the human's response from a review folder (its `response.json`) or a downloaded file (`report.html` too) and prints each reply and new comment with its page line, each Accept or Reject click as `ACCEPT` or `REJECT` with the action it asks for, the applied findings nobody answered as `ACCEPTED`, and the text edits as diff hunks. The first read of a response saves the page as it is then into the review folder (`base.md`). | the file is a review page's response |
| `edit review FOLDER --notes FILE [--check]` | Checks the agent's revision of a page after the human's response: every change since `base.md` must lie inside the quote of a note on the comment, the edits or the chat request that asked for it. Without `--check` it then writes the next review folder, with the notes as comments, and prints its link. | `VERIFIED[revision]`; 1 when a change lies outside every note |
| `doctor [--repo]` | Without `--repo`: the plugin's own files. With it: the project's memory budgets, epistemic tags, memory history chain and layout, and for each configured research system its config, endpoint, MCP servers, capability providers and gitignored secrets. | nothing missing |
| `doctor --repo . --tidy [--apply]` | Lists defuss-vae's leftovers in `tmp/` (session folders untouched for 14 days except the newest, interrupted registry writes, pid files of stopped processes) and check-log archives older than 7 days; `--apply` deletes the leftovers and bundles the archives per day. The project's own `tmp/` files, memory history and logs are never deleted. | always |
| `update version` | The version this copy ships, from its own `plugin.json`. | always |
| `update check [--quiet]` | Fetches the released version (2 s timeout) into the per-user cache and prints a notice when it is newer; the session-start hook runs it detached at most daily. `VAE_UPDATE_CHECK=0` turns the hook's run off. | always |
| `update migrate` | Moves defuss-vae's files (`VERIFY.py`, `MEMORY.md`, `EPISODES.md`, `CLI_GIST.md`, `SWARM_STATUS.yaml`) from `.agents/` to `.vae/` (`git mv` for tracked ones), rewrites the swarm ignore line, refreshes an existing `AGENTS.md` block and leaves every other file in `.agents/`. | nothing to move or moved; exit 2 without change when both folders hold state |
| `research run QUERY [--model ROLE] [--max-rounds N] [--max-tool-calls M] [--no-experiments]` | Deep research on the configured LLM endpoint with the configured capabilities, typed decisions and python3 experiments; writes `evidence.jsonl`, `chains/`, `experiments/`, `report.md`, `report.html` (the review page) and `meta.json` to `tmp/vae/research/<yyyy-mm-dd_hh-mm-ss>_<n>/`, prints `ASK:` lines for questions no human answered. | the report is written within budget; exit 2 with `UNKNOWN[research.budget]` when the tool calls ran out, `UNKNOWN[research]` on a config or endpoint failure |
| `research init` | Scaffolds `.vae/.env.openai`, `.env.mcp`, `.env.typed-decisions` (secrets, mode 600) and their `.json` twins from `templates/research/`, and gitignores `.vae/.env.*`. Never overwrites. | always |
| `research tools` | Lists the LLM roles with the capabilities each declares, the typed-decision endpoint, each MCP server's tools (or why it is unreachable), each capability's providers in fallback order and the CloakBrowser binary. | the config parses |
| `research call CAPABILITY key=value...` | Calls one capability (websearch, webscrape, pdf, document, paper_search, ocr, vision, video, repo_search, repo_file, repo_tree) and prints the text, the provider that answered and every provider that failed before it. | some provider answered |
| `swarm ACTION` | The sub-agent registry `.vae/SWARM_STATUS.yaml` at the main worktree root. `spawn --name --goal --workdir --targets [--eta --ram --vram --disk --gpu --container] -- CMD` starts `CMD` detached, logs each line with a timestamp to `var/log/swarm/<name>.log` and registers it; `set` updates or registers an entry the caller owns; `rm` reaps one; `stop` ends a spawned job (SIGTERM, SIGKILL after 5 s); `status [--fix]` prints free resources and each agent's state and records drift. Every write is re-read after `--settle` seconds (default 3). | the claim holds; `status`: 0 when no agent needs the orchestrator, 1 when one does |

Check results print as `VERIFIED[check]=true|false BC evidence`, so the reason is on the same line as the result; `gate` adds the next instruction for the agent. Architecture and module layering: [`ARCH.md`](ARCH.md).
